## 一、MVP 范围（P0，只做这些）

**一句话**：用户选真大师 → 付费 → 提交问题 → 大师 24h 内图文回复 → 用户查看。

✅ **做**：
1. 真人大师列表（真资质，替换现有 6 个虚构人设）
2. 用户下单页：选大师 + 填问题（生辰/困惑）+ Stripe 付费
3. 大师工作台（简单后台）：待回复队列 → 提交图文回复
4. 用户"我的咨询"页：查看回复 + 一次免费追问
5. 合规护栏（见第五节）

🚫 **明确不做**（防 scope 爬，留给 P1/P2）：
- ❌ 实时语音/视频连麦（要 RTC，烧钱，P2）
- ❌ 按分钟计费（测测诱导消费的坑，MVP 用按次固定价）
- ❌ 复杂钱包/自动分账（MVP 用 Stripe 单次 + 后台记账线下结算）
- ❌ 大师自助入驻审核流（MVP 人工加白名单）

## 二、供给侧（生死线 · 三通道并行）

冷启动顺序：
1. **第一批（真人先跑）**：Karen 的命理师人脉 / 麦玲玲圈子 → 3-5 个真人，最靠谱、最合规。
2. **公开招募兼职大师**：小红书/命理社群发招募，入驻抽成分账。⚠️必须审资质、防造假（测测翻车教训）。
3. **现成平台 API 兜底**：跟高人汇等现成供给谈导流/分成，填补空档。

> ⚠️ 上线前必须至少有 **1 个真人**能真实接单。没真人 = 欺诈 + 踩测测雷。宁可晚上线，不可空气单。

## 三、用户流程

```
masters.html(真大师列表) → 选大师 → 下单页(填问题+生辰+邮箱)
  → Stripe 付费 → 生成 consultation(status=pending)
  → 大师工作台看到 → 写回复 → 提交(status=answered)
  → 用户"我的咨询"查看 + 邮件通知 → 一次免费追问
```

## 四、数据模型（SQLite，复用现有库）

**masters 表**（升级：真人+资质字段）
`id, name, title, avatar_url, exp_years, specialty, rating, price_cents, bio, cert_desc(资质公示), is_active, created_at`

**consultations 表**（新建）
`id, master_id, user_email, question, birth_info, status(pending/answered/refunded), answer, followup_question, followup_answer, amount_cents, paid_at, answered_at, created_at`

## 五、合规护栏（不商量）

1. 大师**真资质公示**（cert_desc 字段，页面展示）
2. **明码标价**，按次固定价，不诱导充值
3. 全页免责："命理内容仅供参考，不构成医疗/投资/法律建议"
4. 咨询记录**留存**（consultations 表持久化）
5. 超时未回复（>24h）**自动可退款**
6. 不做"限时逼单/余额焦虑"等测测式诱导设计

## 六、计费 & 分账（MVP 极简）

- 用户 Stripe 单次付费（复用现有 Stripe，已 connected）
- 平台记账：`amount_cents` 存 consultations
- 分账：MVP **后台导出 + 线下/手动结算**给大师（约定抽成，如平台 30%）。规模化再上自动分账。
