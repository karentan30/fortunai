> 目标：30 天内拿到前 100 个付费用户。北极星 = 免费报告 → 付款转化率 + 7 日回访率。

## W1 先付款，邮箱自动建号（P0）

**用户视角**：看完免费报告 → 点解锁 → 直接进 Stripe 付款页（Stripe 收邮箱）→ 付完回到报告页，已解锁，已自动登录。不用设密码。

**机制**
1. `/api/create-checkout`：Stripe 通道不再要求登录。未登录时生成一次性 claim 随机串，哈希存订单，明文放 httpOnly cookie `sy_claim`（2 小时）。
2. `success_url` = 原报告页 `?paid=1&session_id={CHECKOUT_SESSION_ID}`。
3. 新增 `POST /api/checkout/claim {session_id}`：向 Stripe 核验已付 → 取付款邮箱 →
   - 订单已挂账号 → 当前浏览器若已登录同一账号直接 ok。
   - 订单未挂：按邮箱找账号，没有就建**无密码账号**，订单挂上。
   - **自动登录只在两个条件同时成立时发生**：① 账号是本次付款新建的；② 请求带的 `sy_claim` 与订单哈希一致（同一浏览器发起的付款）。且每单只能自动登录一次。
   - 邮箱已有老账号 → 订单挂到老账号，但**不自动登录**（防止"用别人邮箱付 1 单就登进别人账号"），发登录链接邮件，页面提示"去邮箱点链接打开报告"。
4. Webhook `checkout.session.completed` 同样执行挂单（用户付完就关页面也不丢），并发"你的报告已就绪"邮件（含登录链接）。
5. **邮箱登录链接**（magic link）：`POST /api/auth/magic-link {email, redirect}` 永远返回 200（不泄露账号是否存在）；令牌 30 分钟、单次、只存哈希；`GET /api/auth/magic?t=` 设 cookie 后跳转（redirect 只允许站内路径）。登录页加"用邮箱登录链接"。
6. 国内微信/支付宝通道拿不到邮箱 → 仍要求登录（维持 0913 口径）。
7. 历史单补救脚本：`server/scripts/claim-legacy-orders.js`，对 completed 且无主的 Stripe 单查付款邮箱 → 建号挂单 → 发登录链接。**需在生产执行，要 Karen 放行**。

**验收**：未登录走完 Stripe test 付款 → 回报告页自动解锁；同邮箱二次付款不重复建号；拿别人老账号邮箱付款不会登入该账号；伪造/复用 session_id 无效；magic link 过期/复用失败。
