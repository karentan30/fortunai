### 决策 3️⃣：支付回调策略（可靠性）

**方案**: Webhook + 每日 DB 对账 ✓

```
流程:
1. 用户支付 → Stripe/Toss 返回 clientSecret
2. Webhook 异步推送 payment.success
3. 后端验证签名 + 幂等性检查 + 插入 orders
4. ✓ 返回 200 OK (即使失败也重试)
5. [每天 02:30] 自动对账 Job
   └─ 从 Stripe API 拉当日交易
   └─ 对比本地 DB
   └─ 发现幽灵单据 (支付方有，本地无) → 插入修复
   └─ 发现孤立单据 (本地有，支付方无) → 告警

保证: 幽灵单据 = 0 | 孤立单据 < 1/天
```

**签字同意**:
- [ ] 接受 Webhook + 对账架构
- [ ] 接受 <2s 支付确认延迟（webhook 异步）
- [ ] 每月人工审查对账报告 1 次

## ❓ FAQ · 常问问题

### Q: 为什么法律文件这么重要?

**A**: 没有真实公司信息 = 用户投诉/退款时无法索赔，法律风险无限。香港公司注册号是关键。

### Q: Stripe KRW 为什么不用?

**A**: Stripe Korea 只支持国际卡 (Visa/MC)，韩国用户 90% 用 Toss/Kakao/Naver 本地支付。转化率 <2%，不值得。

### Q: Webhook 丢了怎么办?

**A**: 每天凌晨 2:30 自动对账，从 Stripe API 拉当日交易对比，漏掉的会自动插入 DB。≤24h 最终一致。

### Q: 法务审查要多久?

**A**: 5-7 工作日。建议同步进行开发，最后 2 周再联系外部法务 (更便宜)。

### Q: Karen 需要做什么?

**A**: 
1. 提供公司信息 (1 hour)
2. 签批 PRD (5 min)  
3. 审核法务反馈 (1 hour, 可选)
4. 生产签字放行 (5 min, 3 周后)

**总计**: ~2 小时工作 (分散)
