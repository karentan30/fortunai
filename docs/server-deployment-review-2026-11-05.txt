账号一致性发现
server/lib/store.js 在进程启动时把 DATA_FILE 加载进内存，再将整体 JSON 写回磁盘。
不能启动两个指向同一份原站 data.json 的可写进程。
将 data.json 复制给新进程也不会自动保持账号、会话、订单同步，不能称为共用账号。
因此暂不下发第二个完整生产进程的启动命令，也不直接运行旧 deploy.sh。
正式方案需在以下两种方案间完成代码及现场验证后确定：
1. 原账号服务保持唯一写入方，独立交友服务通过已验证的认证接口使用同一用户身份，完整处理登录失效与退出；
2. 维护窗口中采用单写入方切换，先停旧写入、核验备份、再启动兼容验证通过的新版本，准备回退。
不得为了尽快展示页面而把 friends-preview.cjs 对公网开放为生产服务。

发布前还需现场确认
- 原站代码是否含未提交/未纳入当前仓库的更改；现有 DATA_FILE 的实际位置、备份和恢复验证。
