Runae PRD：生辰先配对与分享获客
版本：2026-11-04 本轮总稿
最新一期优先级（本段优先于此前路径顺序）：注册获客与明确授权的本人私密建档 -> 生成分享卡 -> 好友发现/邀请。匿名免费即时查日主仍保留，但不是强迫注册或保存生日的入口；拒绝保存不阻断匿名即时计算。收费后置，保持未开放。
生辰保存范围已变更：匿名即时计算不保存原生日；用户注册后可以主动、单独同意将自己的birthInput存入私密intake，生产持久化应由加密SQLite及备份覆盖。现有公开profile的chart仍不包含raw生日，不能据此笼统宣传整个平台‘从不保存原生日’。保存生辰、用于后台匹配、用于具体pair关系分析是三个独立授权。
商业产品更新：以用户最新确认的‘双人详细报告按次付费，或月/年会员持续匹配’为当前主线；下方历史个人报告价格方案只保留讨论背景，不能替代这两种独立权益定义。
范围：中文网页；先做好个人卡、分享获客、真实好友发现与双方授权的基础关系指南。本稿不把本地代码、模拟资料或通过测试视为正式上线。

一、产品目标与明确边界
产品一句话：通过五行八字、日主与生肖作为认识的入口，让用户展示真实个人亮点、找到想一起体验生活的朋友或认真了解的婚恋对象。
对外可探索的语言是‘找互相旺的搭子或对象’，产品解释须落实为彼此支持、共同兴趣和互动体验，不承诺五行使人旺运、旺夫、发财、治病或必然适婚。日主相生并不自动等于完整八字相合，更不等于真实关系适配。
核心目标：让用户免费查日主后立即获得可分享的卡片；用自己的亮点和想一起做的事吸引认识申请；让已有喜欢对象的人发专属链接，由双方各自填自己的出生信息，授权后获得基础文化关系指南。
本轮优先级：海报与邀请闭环 > 真实公开用户的发现和建联 > 基础关系指南 > 其他深度功能。不要为了‘Agent’名义扩大开发范围，也不将模型token消耗等同用户价值或商业目标。
上述功能优先级在本次收束中调整为：先注册授权建档和分享获客，再发现/邀请及关系指南；具体次序以上文‘最新一期优先级’为准。

二、目标人群与使用动机
1 北京起步的成年同城用户：想认识朋友、兴趣搭子或认真恋爱的人，有兴趣了解五行但不一定懂排盘。
2 已有一个感兴趣对象的人：希望先有一个轻松话题与关系对照工具，减少直接询问生日的尴尬，同时保留各自出生隐私。
3 不擅长写个人介绍的人：希望把学校、职业、兴趣和真实条件组织成清楚好看的卡片，不愿反复在多个平台输入。
4 不想只吃饭喝咖啡的人：希望通过四个具体、有趣且双方愿意的约会想法更好地展示自己。
不把高净值、名校、年轻或偏瘦体型作为所有人的统一价值标准。职业、收入与资产等均由本人自愿披露，学校或资产条件不能代替关系中的尊重、边界与共同期待。

三、两条主路径
A 从测自己开始，分享并认识新人
第一期主入口先注册/登录 -> 手填本人资料或在本机预览本人其他软件截图、人工复核填入 -> 单独选择是否保存本人生辰 -> 单独选择是否允许后台匹配 -> 保存私密草稿 -> 本人继续生成分享卡并复核公开范围 -> 好友发现/邀请。私密建档不会自动公开或进入可推荐人库。匿名查自己作为并行免费路径继续保留。
首页填写自己的公历/农历出生日期，可选分钟、出生城市等当前排盘所需信息 -> 免费计算日主/生肖与基础五行认识方向 -> 直接生成日主卡 -> 可继续补九项真实亮点、兴趣与四个约会想法 -> 预览三张分享海报 -> 保存PNG并自行发社交平台 -> 访客查看公开分享卡，测自己或注册建档 -> 按双方偏好申请认识 -> 对方同意后展示授权字段与联系方式。
生成后优先展示真实、允许公开且满足可见性规则的好友推荐；当前依据日主/生肖偏好和现有筛选规则，不是所有用户自动经过完整八字筛选。没有真实候选就显示暂时没有合适公开用户，提供分享和邀请动作，不用虚构资料补位。
不能把生成卡片、访问二维码或匿名浏览计为真实用户入库。须完成相应注册、本人建档和公开授权，才可能进入可推荐范围。
B 已有喜欢对象，发专属关系邀请
发起人先填写自己的出生信息/核实自己的日主 -> 创建给这个人的专属邀请链接 -> 将链接自行发给对方 -> 对方打开并注册或登录 -> 独立填写自己的出生资料、查看计算与授权说明 -> 双方明确同意用于这次关系对照 -> 查看基础关系指南与可继续聊的话题。
收件人尚未确定身份时，token邀请只是领取入口，不因任意人打开就自动绑定或暴露发起人私密资料；须按实际实现完成领取、身份绑定、双方授权、撤销和过期控制。
默认不要求发起人代填对方生日，更不能把未经授权取得的生日当对方本人提交或授权。邀请一人、撤销旧邀请、对象不愿填写或拒绝授权，都应有清楚结果。
双方不展示彼此原生日、出生时辰或对方完整四柱，只显示权限允许的基础关系摘要和类似Co-Star的相处指南。‘类似’指关系解读体验，不声称使用相同算法、权利或验证体系。

四、页面信息架构
0 本人授权建档（一期新增独立手机页面，UI/挂载待联调）：账号 -> 输入方式 -> 本人生辰 -> 九项及个人介绍 -> 生辰保存与可选匹配授权 -> 保存私密草稿。已有账号复用登录，不为同一用户另建身份。截图入口只本机预览与手动参考填入，不上传图片、无自动OCR；不能写‘截图一传资料自动完成’。
1 首页：一句产品定位、自己的出生信息表单、免费查日主按钮、已有对象的邀请入口、简短隐私说明。核心操作不被全部扩展功能淹没。
2 日主结果页：自己的日主/生肖、已计算范围及规则、传统五行关系认识方向、生成卡片、看看真实公开好友、邀请喜欢的人。信息不足时说明时柱未知等限制，不能偷偷补成完整盘。
3 我的资料：九项亮点、本人简介、关系意向、城市、兴趣、四个约会想法和每字段可见范围。保存后由本人确认公开版本；自报与认证状态分开。
4 我的三页海报预览：平台尺寸切换、可选本机照片、亮点选择、二维码选择、三张逐张保存；不强制上传照片。
5 发现好友：仅真实公开档案，依据现有日主/生肖偏好及权限展示，空状态诚实显示。点击个人卡进入详情dialog。
6 个人详情dialog：现有权限允许的字段、兴趣、关系意向、日主和生肖；先看双方基础关系入口，再申请认识。该入口不能绕过双方出生用途授权。
7 专属邀请与基础关系页：创建、打开、领取/确认、独立提交、等待对方、双方授权、指南、撤销/过期/拒绝状态。私人关系结果不作为公共获客海报默认内容。
8 建联与隐私：申请/同意/拒绝/撤销、联系方式权限、不再遇见、举报、删除和导出等现有流程。
9 私人问卷：10主题35题，仅本人可查；任何双方摘要需另行授权。不是全部答案自动公开，也不因建联就默认开放问卷。
10 帮助与服务说明：计算范围、公开链接可见性、用户自报、报告状态、客服/主体/留存政策及真实开放状态。

五、分享页与三张海报
对外分享页和海报内容采用三段结构：
第1张‘认识我’：可选照片放顶部；昵称、城市、关系意向与九项真实亮点形成清楚层级；自己的日主/生肖及认识偏好可在本人确认后展示。照片不放时排版仍完整。公开卡只展示用户选择公开的字段。
第2张‘想一起做的事’：四个具体有趣约会/搭子活动，体现爱好、运动水平、频率及新手友好程度；不默认只有吃饭看电影。不写未核实的实时场馆库存、订位成功或优惠。
第3张‘邀请你’：‘对我感兴趣，先看看我们的基础五行关系’与‘测自己的日主，也生成你的卡’两个清楚动作。使用真实对外地址；本地码明确仅本地有效，不能当获客二维码外发。
尺寸：小红书/微信1080×1440；抖音/视频号1080×1920。交付是三张PNG，不是已制作视频；不能写成自动发布或自动生成成片。
小红书二维码默认关闭，可由本人选择打开；该开关是用户选择，不代表平台允许站外导流。发布、商业合作标识及引流方式仍须按目标平台当期规则核实，不提供绕审核方式。
分享动机：清楚展示自己的真实亮点；给感兴趣的人一个低压力认识入口；邀请对方也测自己；把‘想和你做什么’具体化。不能靠假嘉宾、假成功案例、稀缺恐吓或保证旺运促转化。

六、九项资料、年龄、资产与照片
九项统一字段：年龄、身高、体重、学校、职业、行业、title、年收入、个人净资产。表单收集与公开展示是不同决定，敏感条件可不公开；不以未填收入/资产阻断免费日主测算。
职业是做什么，行业是所属领域，title是具体岗位，不能只写一个‘高管’替代三个字段。身高体重仅是本人描述，不形成健康诊断或颜值价值分数。
出生信息为计算输入，公开年龄为展示资料，两者分开说明来源与更新时点；平台不替用户认证假年龄，也不暗示隐藏生日等于年龄已经真实核验。若展示年龄由生日计算，明确截至日期；自填年龄标明本人自报，不伪装成认证。
注册私密生辰保存：独立saveBirthConsent为true才保存birthInput，拒绝时birthInput必须为null；不能让填写生日隐含等于同意长期保存。matchingConsent独立控制后台匹配用途，true要求已同意保存本人生辰；它不等于对任意用户公开、不代替具体pair双方授权，也不意味着已启用完整八字自动排序。用可理解的说明解释用途，不能只显示字段名或一个打包同意所有用途的勾选框。
个人净资产与年收入不同；个人资产与父母家庭资产分别填写，不能把家庭房产、继承预期自动算作个人净资产。A7/A8/A8.2/A9尚未形成统一口径，当前仅为未定义展示标签，不换算金额、不代表权属与认证。统一定义币种、净值/总额、负债和归属前不按A标签推定财富真实性。
照片当前仅供本机海报选择和绘制，不保存到服务器，不等于已经实现个人相册或资料头像上传。默认不放图也能生成分享卡。服务器图片存储、访问控制、删除与内容审核均属未来独立功能。

七、基础关系指南的范围
免费日主结果：自己日主/生肖、已计算四柱范围和文化关系说明。
当前推荐：日主与生肖偏好等现有规则；不称‘完整八字已筛出最合适对象’。
双方基础版：双方各自提交及授权后，对已计算因素作文化对照与相处话题指南，不展示对方原生日/出生时辰/四柱，不判定绝对适婚或‘不合就不能见面’。
完整AI个人报告或完整AI合盘：仍未完成线上实际交付验收，不能把单元测试、stub模型、基础规则对照或非空文本当作已经接通。代码可能有共享生成器、加密作业、计费账本和模拟集成测试，但对外开放须以审计与真实验收为准。个人报告和双方合盘又是不同产品，不互相冒充。
不预测医学诊断、怀孕/生育时间、投资收益或必成婚结果。计算字段、规则推导与AI文字解释要区分；缺信息不能由AI编排补齐。

八、问卷与扩展需求

AI文字/语音访谈自动填问卷、完整AI合盘、资料截图或本人帖文导入、相册/私密视频、站内15分钟语音、位置居中推荐与预订、开放多人成局、商家佣金、认证服务等，不因写入讨论就成为本轮已完成能力。
资料截图一期范围更新：本人可在本机预览自己的其他软件截图并手动填入/复核字段，图片不上传；自动OCR、文字识别回填和本人帖文解析仍未接通。上传前提示只用本人有权使用的资料，含第三人姓名、头像、聊天或联系方式应先裁剪/遮挡，不主动收集旁人聊天和联系方式。平台不得把截图存在本地预览器就当作原平台资料真实性已获认证。

十、验收标准
1 免费入口：未付费也能输入自己的合法日期并获得基础结果与可分享卡；资料不完整时明确限制，不能暗补未知时辰。
1a 注册建档：手填与本人截图本机参考两路均能完成；保存前本人复核；图片不出现在网络请求/后端。saveBirthConsent=false时不保存birthInput；matchingConsent=true但未同意保存时拒绝；具体pair仍另授权。注册私密草稿不自动生成公开profile/listed。expectedRevision冲突不能静默覆盖较新资料；跨用户读写删拒绝，删除本人intake不冒充已删除其他业务记录。
2 信息最小化：计算原生日不通过公开卡、详情、海报、邀请或关系结果泄露；对方四柱与出生城市摘要等未授权字段也不因关系链接泄露。网络响应与图片逐项检查，不只靠UI隐藏。
3 邀请闭环：未登录/错误收件人/重复领取/链接转发/拒绝/撤销/过期/拉黑/删档/并发领取均有可核验的权限结果；双方授权未齐前不生成双人指南。
4 真实推荐：只推荐有公开授权的真实档案；任何虚构100人数据不能出现。无结果、偏好不匹配或当前未覆盖时有诚实空状态，不显示杜撰人数。
