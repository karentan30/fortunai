## 3. 最新用户确认的产品方向（待逐项实现）
主定位：通过五行找人，用户不懂五行也能获得解释；加入真实人库后认识搭子、朋友/闺蜜、约会对象、认真婚恋对象。

个人资料可以完整填写：年龄、身高、体重、学校学历、职业、收入、个人资产、家庭资产、房车户籍等；保留用户亮点。最新“可以全填、信息更多”覆盖上一轮“取消九项资料”的临时建议，但不要自动把敏感资料全部公开。必填与选填应按用途渐进设计。
认真婚恋用户进入之前文章的十方向问卷：家庭/生育分工、财务、未来规划、沟通冲突、亲密关系边界、亲友关系、过往经历、自我认识、兴趣解压、生活习惯。这是十个维度，不是简单十道是非题。自愿跳过或待讨论不是缺陷。
问卷可以辅助后台匹配，原始答案不默认互看；报告不能通过总结泄露未授权答案。AI语音访谈为后续实现，现有文本问卷页面不等于已接通语音。
首个增长实验聚焦一所大学：选择具体学校/校区待用户确定，不假设清北；成年用户、校内距离、共同兴趣、社团朋友传播。不能把自填学校冒充学籍认证。
四种认识目的应分别设计排序与报告；现有存储只有交朋友/找搭子/认真恋爱，不能假称已支持新的全部枚举和多选。
认真婚恋要匹配用户自述的结婚/生育计划，不使用命盘预测实际怀孕日期。

## 4. 双向推荐与认识流程
用户问：A想找180cm/北大毕业的B，B为什么想认识A？
需求：分别收集“我的资料”“我的期待”，期待区分必须满足、优先、不介意；先检查双方认识目的与硬要求，再推荐。A符合B的偏好不等于B已同意；未接受不能写“TA也想认识你”。
逐方解释公开可用的连接点，隐藏筛选条件不泄露。允许不同维度互相欣赏，不输出统一人的价值/竞争力总分。
主链路：测类型→本人确认资料/公开权限→可解释推荐→双方同意认识→预约15分钟语音或视频→私下反馈是否继续。
现有共同时间计算不是完整预约服务。语音/视频没有接入；初期可在双方同意后用微信通话，但时间确认、改期、提醒和反馈仍需实现。不能假装网页里有音视频。
活动先根据爱好推荐3–5个选项，不接商家/场馆/预订。资产高低不是朋友关系的价值判断。

## 5. 分享、报告与付费
输出规划：公开分享卡、双方授权的私密报告、随关系阶段更新的相处指南。

输出：关系摘要、传统依据、双方可验证的互补点、现实共识/差异、三条交流问题、三个活动建议、下一步。
每项结论区分传统文化线索/本人自述/待确认。公开卡不得带原始出生信息、完整四柱或隐藏问卷；双方公开分享需明确确认。
