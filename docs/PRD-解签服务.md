# PRD — 解签服务 (Sign Interpretation Service)

**产品**：Runae（善缘）灵性平台
**功能线**：付费变现功能 · 命理/灵性赛道
**版本**：v1.0（可开工）
**日期**：2026-08-18
**作者**：C端产品（命理/灵性）
**一句话**：用户在寺庙/神社**实体抽了签**，把签带回来，Runae 用**真谱库**给出专业、可信、多语言、结合所问之事的解读——别人收费，我们做得更准更省心。

---

## 0. 与现有功能的本质区别（先说清楚，避免做重复）

现有 `/api/lingqian` 和 `/api/omikuji` 是 **"App 内虚拟摇签"**：后端 `Math.random()` 帮用户抽一个签号/吉凶，然后 LLM **原创**签诗（`divination.js:2843` 明写"四句七言古诗，原创"）。这有两个问题：

1. **签诗是 LLM 编的**，不是真谱文——这恰恰是 `lingqian-guanyin.json` 的 `_meta` 明令禁止的（"禁止LLM改写签文·只解不改·严禁用LLM生成假七言诗顶替"）。
2. 用户**已经在庙里抽过签了**，不需要我们再帮他摇一个。

**解签服务是全新的输入模型**：签号/签文来自**现实世界**（用户手里的实体签），我们的职责是——
- **查真谱库**返回该签的**固定谱文**（一字不改）；
- 在真谱之上，**结合用户具体所问**（事业/姻缘/求财/疾病/失物…）做**解读**（这部分才用 LLM，且被真谱严格约束，不得改写签文本身）。

> 这是本功能的护城河，也是定价能立住的根本理由：**真谱兜底 + 个性化解读**，市面多数竞品要么纯 LLM 瞎编、要么只给死板古文没人味。

## 1. 用户场景 (Personas & Pain)

### 目标用户
- **海外留学生 / 华人游客**：在清水寺、龙山寺、黄大仙祠、四面佛、雍和宫、行天宫等抽到签，想知道到底啥意思。
- **旅居/移民华人**：远离故土仪式感，抽签是情感锚点，但看不懂繁体/古文/日文签。
- **本地信众**：庙里解签要排队、要功德钱、师父三言两语说不透，想要一份能反复看的详细解读。

### 核心痛点
| 痛点 | 现状 | Runae 解法 |
|---|---|---|
| **看不懂签文** | 七言古诗 + 典故（"苏秦不第""董永卖身"），现代人读不懂 | 白话逐句翻译 + 典故背景 |
| **不知对我意味什么** | 签文泛指，没结合"我问的事" | 用户选所问之事，解读定向到事业/姻缘/求财… |
| **庙里解签排队/收费/说不透** | 排长队、给功德钱、师父一句"还行" | 随时随地、一份可反复看的完整解读 |
| **语言不通** | 日本 omikuji 全日文、港台繁体 | 多语言（中/英/日/韩），留学生海外刚需 |
| **怕解错/被 App 瞎编** | 竞品 LLM 乱编签诗 | 真谱库兜底，签文一字不改，可信 |

### 典型用户旅程（Job Story）
> "当我在清水寺抽到一支我看不懂的签时，我想拍张照或输入签号，就能立刻得到一份**白话、结合我正在纠结的事、我看得懂的语言**的专业解读，这样我不用排队问师父，也不用担心 App 在瞎编。"

## 2. 支持的签系 (Sign Systems) — 分批策略

| 签系 | 签数 | 真谱来源 | 现有资产 | 批次 |
|---|---|---|---|---|
| **观音灵签** | 100 签 | `lingqian-guanyin.json`（1 签已 verified，99 待补） | ✅ 有库 + `/api/lingqian` 逻辑 | **P0（第一批）** |
| **日本 omikuji（御神签）** | 按吉凶等级（大吉→大凶 7 级） | `/api/omikuji` 已有等级 + 分档报告逻辑 | ✅ 有逻辑 | **P0（第一批）** |
| **关帝灵签（关圣帝君）** | 100 签 | 需补真谱（WebFetch 抓公共谱文） | 复用 lingqian 数据结构 | P1 |
| **黄大仙灵签** | 100 签（港澳/东南亚高频） | 需补真谱 | 复用结构 | P1 |
| **妈祖灵签（天后 / 六十甲子签）** | 60 签 | 需补真谱 | 复用结构 | P1 |
| **泰国四面佛签（Erawan）** | 通常 27/28 支 | 需补真谱（英泰对照多） | 需单独结构（无诗，多为箴言） | P2 |
| **吕祖灵签 / 车公签 / 月老签** | 视需求 | 需补真谱 | 复用结构 | P2（按数据看板热度决定） |

**第一批做哪些 = 观音灵签 + omikuji。** 理由：
1. **签库与端点逻辑已存在**（`lingqian-guanyin.json` + `/api/lingqian` + `/api/omikuji`），改造成本最低。
2. 观音灵签是华人世界流通最广的签系（各地寺庙通用同一套 100 签谱），一套真谱覆盖大量寺庙。
3. omikuji 覆盖日本全部神社的留学生/游客场景，且它按**吉凶等级**解读、不依赖逐签固定诗，补数据成本低。

> ⚠️ P0 上线前置硬条件：**观音灵签 100 签必须全部 verified=true**（当前仅 1 签）。补谱走 **WebFetch 抓公共传统谱文**（观音签谱属公共文化、无版权），**严禁 LLM 生成假诗顶替**。这是本功能可信度的生命线。

## 3. 输入方式 (Input Methods) — P0/P1

| # | 方式 | 体验 | 开发成本 | 优先级 |
|---|---|---|---|---|
| ① | **选签系 + 输签号** | 最简单可靠，直接查真谱 | 低（查库即可） | **P0** |
| ② | **拍签文照片 OCR 识别** | 体验最好（不用手输），海外用户友好 | 高（vision + 签号/签系识别 + 兜底） | **P1** |
| ③ | **手动输签文（粘贴/打字）** | 兜底，签号磨损看不清时可用 | 低（模糊匹配诗句 → 命中签号） | **P1** |

### ① 输签号（P0）
- 用户先选签系（观音灵签 / omikuji），观音灵签再输 **1–100** 的签号；omikuji 选**自己抽到的吉凶等级**（大吉/吉/中吉/小吉/末吉/凶/大凶——签纸上一定印了等级）。
- 后端**查真谱库**返回固定谱文，LLM 只做解读。

### ② 拍照 OCR（P1）
- 复用 `analyzeFace/analyzePalm` 那套 vision 管线（`server/lib/vision.js`），扩展一个 `analyzeSign(imageBase64)`。
- vision 任务：从签纸照片提取 **①签号（"第X签"）②吉凶等级 ③签诗文字**。
- **关键兜底**：OCR 出签号 → **回到真谱库拿标准谱文**（不直接信 OCR 出来的诗，防 OCR 错字污染谱文）。OCR 只用来**定位是哪一支签**，谱文永远以库为准。
- OCR 失败/置信度低 → 优雅降级到「请手输签号」（②③ 之间无缝切换）。

### ③ 手输签文（P1）
- 用户粘贴/打字签诗 → 后端对该签系真谱做**诗句模糊匹配**（去标点、按字比对）命中签号 → 走标准路径。
- 匹配不到 → 提示「请核对签号」或走纯解读兜底（明确标注"未在真谱库匹配到，以下为通用解读"）。

## 4. 核心差异化 (Differentiation)

1. **真谱库兜底**：签文来自 `lingqian-guanyin.json`（verified 真签），**一字不改**。竞品普遍 LLM 瞎编签诗——我们不。
2. **结合所问之事**：用户选择本次所问（事业/姻缘/求财/疾病/失物/出行/诉讼/搬迁…），解读**定向**，不是泛泛而谈。签谱本身对各事项有传统简断（观音签"meaning"字段已含功名/婚姻/财运/疾病/失物），LLM 在此约束下展开。
3. **多签系**：一个入口解全世界的签（观音/关帝/黄大仙/omikuji/四面佛…），旅行/留学场景通吃。
4. **多语言**：中/英/日/韩。留学生"日文签看不懂"是刚需痛点，直接命中。复用现有 `langSuffix(lang)` + `DISCLAIMER_EN/ZH`。
5. **可反复看 + 可追问**：解读入库，支持 `/api/ask-followup` 追问（已有端点）。

## 5. 合规红线 (Compliance) — 死守

> 沿用 Runae 全局合规基线（`DISCLAIMER_ZH/EN`、传统文化寓意、不作效果承诺）。本功能额外强调：

1. **签文是传统固定谱文，一字不改、不改写、不"优化"**。谱文来自公共传统文化，只解释不创作。
2. **解读为娱乐/文化参考**，每份结尾附娱乐免责（复用 `DISCLAIMER_ZH/EN`）。
3. **不承诺灵验、不打包票**（"必发财""一定成""包治病"全禁）。
4. **不恐吓**：抽到"凶/大凶"签时，语气必须**安抚 + 给转念/化解方向**，绝不制造焦虑或恐吓用户去消费化解（参考 Slim 健康红线、彩镜防容貌焦虑同一价值观）。
5. **疾病签只做情绪疏导，不作医疗诊断/建议**（复用 omikuji 现有"wellness angle only, no medical diagnoses"约束）。
6. **不暴露 AI 模型**（复用现有"Never mention which AI model powers this"），文案用中性"our secure AI"。
7. **化解建议**（如推荐手串/祈福）须标"传统习俗心意·不作效果承诺"，且**不得利用凶签制造恐慌来带货**——建议温和、可选、非必需。

## 8. 技术复用与新增 (Tech: Reuse & Build)

### 复用
- **签库**：`server/data/lingqian-guanyin.json`（观音 100 签结构：`no/grade/gong/poem/explain/meaning/verified`）。
- **端点逻辑**：`/api/lingqian`、`/api/omikuji` 的分档（`resolveReportTier`）、gate（`gateMessages`）、免责（`DISCLAIMER_ZH/EN`）、多语言（`langSuffix`）、追问（`/api/ask-followup`）、上下文保存（`saveQaContext`）、带货（`matchProduct` / `products.js`）、代烧（`/offering-plan`）。
- **vision 管线**：`server/lib/vision.js` 的 `analyzeFace/analyzePalm` 模式 → 扩展 `analyzeSign`。
- **支付/地理定价**：现有 Stripe / 微信 / 支付宝 + GEO-PRICING。

### 新增（改造，非重造）
1. **改造 `/api/lingqian` → 真谱模式**（P0，核心）：
   - **不再 `Math.random()` 摇签、不再 LLM 原创诗**。
   - 接收 `{ system, signNo, question, topic, lang }` → **查库拿固定谱文** → 谱文放进 prompt 作为**只读事实**，LLM 只解读、明令"禁止改写签诗"。
   - 建议新端点 `POST /api/jieqian`（解签），保留旧 `/api/lingqian`（虚拟摇签）不动，二者并存、语义清晰。
2. **多签系签库**（P1）：`data/lingqian-guandi.json`、`lingqian-huangdaxian.json`、`lingqian-mazu.json`、`sign-erawan.json`——**同结构**，真谱走 **WebFetch 抓公共传统谱文**，**不用 LLM 编**。四面佛签需要变体结构（多为箴言非七言诗）。
3. **`analyzeSign(imageBase64)`**（P1）：vision 提签号/等级/诗句 → 回库取标准谱文。低置信降级手输。
4. **签系配置表**：`data/sign-systems.json` 定义每签系（名称/多语言名/签数/库文件/输入类型/关联寺庙），供前端下拉 + 圣地图入口映射。

### 补真谱的硬约束（记忆铁律）
> 观音/关帝/黄大仙/妈祖签谱皆属**公共传统文化**，用 **WebFetch 抓取固定谱文**逐签补入 `verified=true`。**严禁 LLM 生成假七言诗顶替**（`lingqian-guanyin.json._meta` 明令）。补完必须**人工/独立 agent 抽验**签诗与权威谱文一致再置 verified。

## 9. MVP 切法 (Minimum Launchable)

**MVP 一句话**：观音灵签 + 日本御神签，用户**选签系 + 输签号/等级 + 选所问之事**，后端**查真谱库**返回固定签文，LLM 结合所问给出白话专业解读，免费预览签文+吉凶、付费（¥9.9/$6.9）解全。

**MVP 范围（P0）**：
- ✅ 输入方式①（输签号/选等级）；② ③ 拍照/手输留 P1。
- ✅ 签系：观音灵签（**100 签全部 verified**）+ omikuji（等级制）。
- ✅ 所问之事单选（可跳过）。
- ✅ 免费预览 → 付费解全（复用付费门 + 地理定价）。
- ✅ 多语言：中 + 英（日/韩 P1）。
- ✅ 合规免责 + 凶签安抚 + 不暴露模型。
- ✅ 独立入口卡（圣地图交互入口 P1）。

**MVP 不做**：拍照 OCR、关帝/黄大仙/妈祖/四面佛、圣地图可点交互、韩语。

**MVP 上线前置硬门槛**：
1. 观音 100 签真谱全部补齐并 verified（WebFetch，独立 agent 抽验）。
2. 付费全链路真跑通（curl 端点出真报告、不撞超时、地理定价对、支付回调通）——**交付给 Karen 前自己先端到端跑通"真能出解读"**（记忆铁律）。
