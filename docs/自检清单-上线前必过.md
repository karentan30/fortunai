# 善缘上线前自检清单

> 每次做完新功能或改动，必须过这份清单。全绿才能 git push。

---

## 一、每个页面都要过（通用5条）

| # | 检查项 | 怎么验 |
|---|-------|-------|
| 1 | **首屏3秒测试** | 打开页面，遮住下半屏，陌生人能看懂"这是什么、我能得到什么"吗？ |
| 2 | **主按钮点击有反馈** | 点主CTA，按钮是否立刻变灰/加载中/文字改变？（绝不能无响应） |
| 3 | **免责声明存在** | 页面上有"仅供娱乐参考，不代替医学/法律/投资建议"字样 |
| 4 | **手机宽度检查** | Chrome DevTools → 375px宽，所有内容不横溢、按钮不重叠 |
| 5 | **死链检查** | 页面上所有按钮/链接点一遍，没有 href="#" 且无动作的死按钮 |

---

## 二、有表单的页面（必填验证）

| # | 检查项 | 怎么验 |
|---|-------|-------|
| 6 | **空表单提交** | 什么都不填直接点提交，应该有红色提示，不能静默无反应 |
| 7 | **提交中防重复点** | 提交后快速再点一次，按钮应该已禁用，不能发两次请求 |
| 8 | **提交失败不静默** | 断网/后端报错时，用户能看到错误提示（不能显示成功） |
| 9 | **成功后状态清晰** | 提交成功后，用户知道"下一步是什么"（等待/去哪里看结果） |

---

## 三、付费功能专项（最容易出P0）

> 这是最重要的一关。每次新做付费功能必须模拟走完全流程。

| # | 检查项 | 怎么验 |
|---|-------|-------|
| 10 | **付款前：价格清晰** | 用户在付款前能清楚看到"我要付多少钱，能得到什么" |
| 11 | **模拟付款回调** | 在浏览器地址栏手动加 `?paid=1&product=xxx`，或在console执行 `localStorage.setItem('sy_paid_xxx','1')`，然后刷新，**结果必须显示** |
| 12 | **付款后不空白** | 结果容器不能是 display:none，付款回调后必须visible |
| 13 | **付款后内容完整** | 不只是容器可见，所有字段（标题/内容/建议）都有数据，不能有空白区块 |
| 14 | **付款后有下一步** | 结果页底部有"分享"或"继续探索"引导，用户不会陷入死路 |

**模拟付款回调的快捷命令（在浏览器Console执行）：**
```javascript
// 模拟八字报告已付款
localStorage.setItem('sy_unlock_a', '1');
location.reload();

// 模拟断事问卦已付款
localStorage.setItem('sy_paid_duanshi', '1');
location.reload();

// 模拟合婚完整报告已付款
localStorage.setItem('sy_hehun_paid', '1');
location.reload();
```

## 四、AI生成功能专项

| # | 检查项 | 怎么验 |
|---|-------|-------|
| 15 | **生成中有loading** | 点击生成，必须看到转圈/进度条/骨架屏，不能空白等待 |
| 16 | **生成失败有提示** | 断网或API报错，页面显示"生成失败，请重试"，不能白屏 |
| 17 | **结果区初始不显示** | 结果容器默认hidden，不能在生成前就显示空的结果框 |
| 18 | **流式输出不断行** | 如果用SSE流式输出，检查文字是否完整，不能被截断 |

## 六、上线前最终门禁（git push 前）

```
□ 以上1-20条全部绿色
□ 新功能的付款回调已手动模拟验证（第11-14条）
□ 在375px手机宽度下截图确认无布局问题
□ 新增的API路由已在server/routes/下确认存在
□ 没有 console.log 调试信息残留在生产代码
□ 没有 TODO / FIXME / placeholder 注释残留
```

---

## 七、AI生成代码后的专项检查（防通病）

每次让AI写完代码，额外检查这5个AI最容易犯的错：

| 通病 | 检查方式 |
|-----|---------|
| 结果容器display:none忘改 | 搜索 `display:none`，确认付款/生成后会被移除 |
| CSS变量用了但没定义 | 搜索 `var(--`，确认每个变量在:root里有定义 |
| 函数调用但没定义 | 搜索 `showToast(`，确认函数在调用前已定义 |
| 年份范围太窄 | 搜索 `option`年份，确认上限是当前年-1以上 |
| 静默失败的catch | 搜索 `.catch(`，确认每个catch里有用户可见的错误提示 |
