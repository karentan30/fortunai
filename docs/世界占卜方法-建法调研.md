# 世界占卜方法建法调研
> 日期：2026-08-18 | 目标：为 Runae 平台新增 6 种世界占卜方法

---

## 背景：Runae 现有模式

现有两套可复用模板：

**A. 抽签+LLM 模式（`/api/lingqian`）**
```
随机数 → 签型(上上签/中签…) → LLM 按角色+签型生成解读
```
无任何外部 API，纯靠随机+提示词。

**B. 符号数据集+LLM 模式（`/api/tarot`）**
```
前端传 cards 数组(name+position+reversed) → LLM 按牌义逐一解读
```
数据集（78张牌名+正逆位含义）由前端或硬编码持有，不需要外部 API。

**结论**：任何"抽符号→解读"类方法，0 天接入外部服务，只需一份符号数据集 + LLM prompt。

## 1. 北欧卢恩符文 Runes ⭐ 最高优先级

### 建法
**A：复用 tarot 模式**，完全无需外部 API。

### 数据集从哪来
Elder Futhark 24 符文（按 3 Aett 分组），数据非常标准化，公开资料极丰富：
- GitHub `bebyx/runepal`：CLI 项目，含每符文的占卜含义，CSV 格式，可转 JSON
- GitHub `topics/elder-futhark-runes`：多个开源实现
- 网站 labyrinthos.co / otherworldlyoracle.com 均有完整 24 符文正逆位含义，可人工整理为 JSON（1小时内完成）

**数据结构样例（24条）**：
```json
{
  "name": "Fehu",
  "unicode": "ᚠ",
  "aett": 1,
  "keywords": ["财富", "丰盛", "起点"],
  "upright": "新的财富周期开启，物质与精神的收获...",
  "reversed": "财富流失，需重新评估价值观..."
}
```

### 工作量
**小（1天）**：整理 24 条 JSON 数据（0.5天）+ 复制 tarot 路由改参数（0.5天）

### Runae 品牌契合度
极高——品牌名 Runae 直接来自 Rune，这是"门面功能"，强烈建议第一个做。

## 2. 西非 Ifá 伊法占卜（256 Odu）

### 建法
**A：复用 lingqian/tarot 模式**，不需要外部 API，但数据集工作量较大。

### 实现思路
Ifá 的核心逻辑：
- 16 个主 Odu（Meji）为基础，两两组合得 256 个 Odu
- 每次"抽签"本质是随机取一个 Odu 编号（1-256）
- LLM 角色扮演 Babalawo（伊法祭司），按 Odu 主题生成解读

**数据集**：
- 无现成 JSON GitHub 库，但 oshaeifa.com 有 256 Odu 英文含义网页
- afrikaiswoke.com 有 16 Meji 含义文章
- scribd 上有 PDF 文档（273979845）
- **实际可行方案**：只做 16 个主 Meji（不做全 256），已覆盖核心，工作量减半。数据整理约 2-3 小时

**数据结构样例（16条）**：
```json
{
  "id": 1,
  "name": "Ogbe",
  "binary": "||||",
  "themes": ["光明", "新生", "神圣力量"],
  "message": "Ogbe 代表白色的力量，生命的初始..."
}
```

### 工作量
**中（2天）**：16 Meji 数据整理（1天）+ 路由 + 角色 prompt 打磨（1天）

### 独特卖点
全网几乎没有英文 AI Ifá 产品，文化新颖，非洲海外华人用户+对非洲灵性感兴趣的西方用户都是受众。

## 3. 凯尔特 Ogham

### 建法
**A：复用 tarot 模式**，完全无需外部 API，数据量最小。

### 数据集从哪来
- Ogham 共 20 个传统字母（Feda）+ 5 个扩展字母（Forfeda），总计 25 个
- 每个字母对应：拼音、爱尔兰语名、树木、颜色、占卜含义
- oghamlore.com、globalspiritualstudies.com、learnreligions.com 均有完整列表
- **无 GitHub JSON 库**，但 20 条数据手工整理只需 1 小时

**数据结构样例（20-25条）**：
```json
{
  "name": "Beith",
  "letter": "B",
  "tree": "Birch",
  "meaning_keywords": ["新开始", "净化", "更新"],
  "divination": "你正站在新篇章的起点，需要放下旧习..."
}
```

### 工作量
**小（1天）**：数据整理（0.5天）+ 路由（0.5天）

### 备注
Ogham 在西方神秘学（Pagan/Wicca）圈有稳定受众，但相比卢恩符文知名度低，可作为第二批次功能。

## 4. 日本九星気学 + おみくじ灵签

> 两个独立子功能，分别讨论。

### 4a. 九星気学（Kyūsei Kigaku）

### 建法
**B：需要历法计算**，但算法简单，可纯手写，无需外部库。

### 算法说明
- 根据生年（+立春修正，2月4日为界）计算本命星（1-9）
- 公式：`(10 - ((year - 2) % 9)) % 9`（Sonoda 1908 年公式，公版）
- 立春前出生者用前一年计算
- 月命星（tsukimei）由本命星和出生月推算，有固定对照表

**现成资源**：
- npm 包 `iztro` 为紫微斗数，不适用
- 未找到专用 Node.js/Python 开源库（九星気学太小众）
- **结论**：算法极简，直接手写 30 行 JS，比找库更快

**九星含义数据**（9条，极少）：
```json
{
  "star": 1,
  "name": "一白水星",
  "element": "水",
  "personality": ["智慧", "灵活", "善于交流"],
  "fortune": "水象征流动与变化，今年运势随机应变..."
}
```

### 工作量
**小（1天）**：算法实现 30 行（3小时）+ 9星含义数据整理（1小时）+ 路由（2小时）

### 4b. おみくじ（Omikuji 御神签）

### 建法
**A：直接复用 lingqian 模式**，几乎零额外工作。

- 日本神社抽签：大吉/中吉/小吉/吉/半吉/末吉/凶/大凶，共8级

- 语言：可选日语或英语

### 工作量
**极小（0.5天）**：复制 lingqian 路由，改签级列表 + prompt 换成日式风格

## 5. 埃及/巴比伦/阿拉伯占星

### 建法
**B：需要星历计算**，但有现成高质量开源库，AGPLv3 需注意授权。

### 可用库

| 库 | 语言 | 授权 | 传统覆盖 | 说明 |
|---|---|---|---|---|
| `xalen-ephemeris` (vedika-io) | Rust + Python/npm WASM | Apache-2.0 | 12+传统含埃及/巴比伦/波斯/97个阿拉伯宫位 | 2026年新项目，验证精度对齐 NASA JPL DE440 |
| `pyswisseph` | Python | AGPLv3 | 西方标准，含巴比伦 ayanamsa | 行业标准，但网络服务须开源 |

**推荐**：`xalen-ephemeris`（Apache-2.0 无传染性），pip install xalen 或 npm @xalen/wasm

### 实现路径
1. 用户输入出生年月日时 + 地点（经纬度）
2. 调用 xalen 计算行星位置 + 阿拉伯宫位（Arabic Lots）+ 巴比伦 ayanamsa 校正
3. 将计算结果结构化传入 LLM，角色为"古埃及/巴比伦占星师"，生成解读

### 工作量
**大（3-5天）**：
- xalen 库集成 + API 封装（2天）
- 输出结构化星盘数据 → LLM prompt 设计（1天）
- 前端输入界面（地点选择/经纬度）（1-2天）
- 注意：服务器需支持 Python 或 Node.js WASM

### 备注
这是本列表里唯一需要真实天文计算的功能，工作量最大但差异化最强。建议等前几个符号类功能验证了市场再做。

## 6. 美洲原住民药轮 Medicine Wheel

### 建法
**A：复用 tarot/lingqian 混合模式**，无需外部 API。

### 数据集从哪来
- 药轮核心结构：4个方向（东/南/西/北）× 4个元素（火/水/土/风）× 动物图腾（36种）
- 问卜逻辑：根据出生月份定"图腾动物"（Medicine Wheel Zodiac，类似星座），加抽当日方向
- **无专用 GitHub 库**，但数据量极少，36条图腾含义可在 legendsofamerica.com / kachinahouse.com 整理

**重要注意**：药轮原属不同部落各有差异，现代商业版本多为 Sun Bear 的"Medicine Wheel"书（1980s），已脱离纯原住民传统成为新时代灵性产品。Runae 应注明"inspired by Medicine Wheel traditions"，避免文化挪用指责。

**数据结构（36条图腾）**：
```json
{
  "month_range": "Dec 22 - Jan 19",
  "totem": "Snow Goose",
  "direction": "North",
  "element": "Earth",
  "clan": "Turtle",
  "keywords": ["耐心", "传统", "实干"],
  "message": "雪雁教导我们在寒冬中坚持，找到内心的温暖..."
}
```

### 工作量
**中（2天）**：数据整理36条图腾（1天）+ 路由+生日→图腾算法+prompt（1天）
