### 3.1 新报告 v4：哪里合 / 哪里要磨合 / 相处建议

**（1109 Karen 改）规则在服务端算，文字由 DeepSeek 写**（仓库已有 `server/lib/llm.js` 的 `deepseekChat`）：
- 服务端先排盘 + 算规则命中（下表），只把「命盘干支 + 命中规则 + 档位」交给 DeepSeek，**不传生日、时辰、城市、昵称**；模型不自行排盘、不新增规则外结论。
- 要有玄学味：用日主、配偶宫、相生相克、刚柔、古籍句等传统说法写；禁用词照旧。
- 生成后过检查（禁用词、百分比、邀请模式下不得出现对方的四柱字）；不通过重试 1 次，再不过就退回固定文案库。
- 每个配对只生成一次并缓存（免费版与完整版一次生成、服务端截断）。
- 页面标注「AI 辅助生成」（AI 生成合成内容标识要求）。
- **命盘显示（1109 Karen 最终定）**：
  - **自己合盘（同一人输入两人）**：两人四柱全显示。
  - **邀请合盘（两人分别输入）**：各自只看到自己的完整四柱；对方只显示日主，其余柱「？」。生克合冲**逐柱全部写出**（年/月/日/时的干、支各是生/克/合/冲/刑/害哪一种 + 2~3 句解读），但不露对方的干支字。扫描规则：对方的年/月/时柱干支字、日支字不得出现在返回内容中。
  - **1109 Karen 定（选项1）**：保留逐柱详细写法；关系名可让人推出对方大半八字，因此**被邀请人填写页必须明示**「对方会看到你们每一柱是合/克/冲，可能据此推测你的部分八字，但看不到你的生日」，勾选同意后才能提交。
  - **紫微**：本期不进合盘报告，下一期做单独付费项（需准确时辰）。

- 一个日支组合只取**一个**类别，优先级：六合 > 六冲 > 刑 > 害 > 三合。同支且不构成自刑（如子子）记 0 分，归「中性」，不出合/磨合条目。
- 落档：先跑 1 万对随机生辰模拟，把阈值定在约「很合拍 30% / 大体合拍 50% / 需要磨合 20%」，阈值写进配置并附模拟脚本。初值：≥3 / 0~2 / <0。
- **姻缘分（1109 Karen 批）**：百分制，= 4 个小分相加，每项 0~25，不设保底：
  1. **天干**：日干生/同/克 + 其余三柱天干五合；
  2. **地支·配偶宫**：日支六合/三合/冲/刑/害 + 其余地支合冲；
  3. **五行互补**：互补加分、同缺扣分；
  4. **夫妻星**：男看财星、女看官杀，看对方日干是不是自己的夫妻星、自己盘里夫妻星强弱；**同性或搭子目的时换成「相处星」**（比劫/印星互动），页面写明。
  - 每项基准 15 分，命中规则按分值 ×4 加减，截到 0~25。用 1 万对随机生辰模拟定基准，目标中位数约 70；档名按分数：很合拍 / 大体合拍 / 磨合型（阈值按 30%/50%/20% 定，写进配置）。
  - 同一对永远同一个分（确定性计算 + 缓存），DeepSeek 只写解释、不碰分数。
  - 免费：总分 + 档名 + 一句总述（可晒分享图，只有分数和档名，无干支）；完整版：4 个小分 + 每项加/扣分原因。
  - 页面固定写「按传统合婚规则计分，仅供参考」。低分叫「磨合型」，禁写「不合适/不配」。
- 时辰：**任一方**没有时辰，双方都只用年/月/日三柱计五行，报告标「有限参考」。

**报告结构**
1. 姻缘分（百分制）+ 档名 + 一句总述；完整版展开 4 个小分。
2. 合的地方（命中的正分规则，最多 3 条）。
3. 要磨合的地方（命中的负分规则，最多 3 条），每条写成"容易在什么事上起摩擦"。
4. 每个磨合点配 2~3 条**相处建议**：只写相处方式和一起做的活动（例：吵架先约定暂停 20 分钟；大事各列三条再谈；一起做需要配合的运动）。不写颜色、方位、物件、择日。
5. 依据（可折叠）：**对外只用粗类**——地支只分「和合类」（六合/三合）和「张力类」（冲/刑/害），天干只分「相生/同类」和「相克」，五行只说「有互补」或「有同缺」。**不写柱位、方向、任何干支字、缺/旺的是哪一行**。合/磨合条目的文案也按粗类写，不按细规则写。
6. 底部固定：「传统文化参考，不预测关系结果，不替代你们的真实相处。」

**防反推**
- 粗类之后，知道自己日支也推不出对方唯一日支（每类对应多个可能）。
- 自己合盘**每账号每天 3 次**，防止拿候选生日反复试、再去对照邀请报告逐一排除。
- v4 授权文案明说：「报告里的合/磨合类别，可能让对方推出你命盘的一小部分。」
- 扫描检查（只防回归）：**只扫依据区和与对方相关的字段**，单个干支字、五行字出现即报错。用户自己的日主、发现页公开日主、普通词（火锅、金钱）不在扫描范围。

**授权版本**：新增 `compatibility-guide-v4`。`friends-compatibility.js` 里授权版本由单一常量改为**接受列表 [v3, v4]**，状态更新、聊天、报告三处一起改。已有 v3 配对：继续看 v3 旧指南，页面提示「重新授权可看新版」，双方都重授 v4 后出新版；不自动迁移。

### 3.2 免费 vs 完整版
- **免费**：姻缘总分 + 档位 + 合的地方 + 1 条磨合点**连同它的相处建议**（不制造焦虑）；其余磨合点显示「还有 N 条」。
- **完整版**：全部磨合点 + 建议 + 依据。**任何一方解锁，双方都能看完整版**（被邀请人不用付钱就能看全，这是推动对方愿意继续、愿意入池的最大钩子）。
- **磨合点 ≤1 条时不卖完整版**：免费已全部展示，页面写「你们的报告已全部展示」，不出付费按钮（避免收钱给空内容）。
- **免费截断在服务端做**：未解锁时接口只返回免费部分和「还有 N 条」，前端拿不到被锁内容。
- **权益设计（配对级解锁）**
  - 不走现有 `friends-pair-reports` 的大模型任务链（它要目的/阶段且绑模型）；v4 完整版是确定性生成，直接由配对上的解锁标记控制：`unlockedAt / unlockedBy / source(单买订单号或会员份额)`。
  - 解锁后双方读同一份完整版。
  - 单买退款：清除解锁标记，双方同时失去完整版。
  - 会员用月度份额解锁后退会员：已解锁的报告**一并撤回**（与会员撤权一致）；退款钩子要能找到该会员份额解锁过的配对。
  - 解锁后**对方撤回授权**：付费方也看不到了。规则：解锁后 7 天内对方撤回，**且付费方还没打开过完整版**，单买自动退款、会员份额退回；打开过或超过 7 天不退（防串通退款）。付费前页面明示这条。
  - 扣次：会员月度份额记在 `friends-membership` 现有权益账本里，按自然月重置；扣次幂等键 = `解锁对象ID(配对ID或自己合盘记录ID) + 用户ID + v4`，同一键只扣一次；解锁写入失败则回滚扣次。
- `friends-membership.js`：新增 SKU `friends_pair_report_v2`（单次，价格待定，建议 9.9 元），`pilot` 关掉；月/年会员 `monthlyReportCredits` 由 0 改为 2。
- 收款沿用现有支付通道；上线前先小额真付一笔，走通"付款→解锁→双方可见→退款→双方撤回"。

### 3.3 自己合盘（自己填两个人）
- 入口：合盘页第二个选项「我知道两个人的生辰，自己看」。
- 必须**三项都勾**才能算：①我已告知对方并获得同意 ②结果只供我本人参考 ③对方已满 18 岁。
- 对方**不建档、不进人才池、不出现在任何推荐、不收通知**；结果不能生成分享卡。
- 对方生辰**只算不存，不进日志**（请求日志对该接口脱敏 body）。用户可选「保存这次结果」：只存档位 + 文案 ID 列表，**不存任何一方的四柱**；可一键删除。
- 走同一套免费/完整版规则。**付费前强制保存这次结果**，解锁标记挂在这条保存记录上；用户删除记录时提示「已付费内容将一并删除」。
- 限次：每账号每天 3 次，同时按设备 + IP 每天限次（防多号绕过）。压测确认粗类之后一份报告对应的候选生日 ≥100 个。
- 结果页底部：「想让 TA 也看看？发邀请链接给 TA 本人填」→ 进邀请合盘（拉新口子）。

### 3.4 邀请后入人才池
- 对方看完报告后弹一次：「要不要让相生帮你认识更多合拍的人？」
- 同意需要**单独勾选**："允许相生用我刚填的生辰建立我的交友卡，并推荐给其他用户"（这是新用途，不能沿用双人授权）。默认不勾。
- 同意的**那一刻**就把对方本人的生辰计算结果复制进他自己的交友卡（因为配对撤回/到期会清空授权数据，不能事后再取）。
- 之后进入现有建卡流程。资料可见范围**沿用现有默认全私密**；页面给一个「一键公开推荐的三项：日主 / 年龄段 / 爱好」按钮，用户自己点。
- 不同意：只保留这次合盘；以后可在「我的」里再开。
- 撤回入池：24 小时内从推荐中消失。
- 年龄对外只显示年龄段（如 25-29）。

### 3.5 私域入口
