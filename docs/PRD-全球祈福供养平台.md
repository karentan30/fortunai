## 第一章 合规与资金模式（最重要·最高优先级）

> 本章是整个产品的地基。所有 SKU 设计、文案口径、支付接入、对外宣传必须先过本章红线，再谈增长。

### 1.1 核心法律风险识别

代祈福/供养业务横跨三个强监管领域，必须逐一厘清边界：

| 风险领域 | 触发条件 | 后果 |
|---|---|---|
| **资金传输牌照（MTL）** | 代收用户捐款再转给寺庙/机构，中间托管资金 | 美国各州均需 MTL，违者刑事责任 |
| **慈善募捐注册** | 以"为寺庙/公益"名义向公众募款，未经州注册 | 虚假募捐罪，Stripe/PayPal 冻账并上报 |
| **跨境 AML/KYC** | 资金从用户经平台流向境外宗教机构 | OFAC 合规、FinCEN 报告义务 |
| **大陆宗教事务监管** | 经营境外宗教服务收款、涉及跨境宗教资金 | 《宗教事务条例》合规风险 |
| **虚假广告/消费欺诈** | 承诺"必灵/改命/治病/保证消灾" | 各国消费保护法，FTC（美）、ACCC（澳）追罚 |

**核心判断：一旦"代收捐款再转给机构" = 资金传输/慈善募捐牌照范畴，且需机构真实授权，否则 = 虚假募捐。**

### 1.2 主方案 A（推荐·立即可执行）：引流撮合 + 服务费模式

#### 方案逻辑

```
用户 ──付服务费──► Merit 平台（收"代办服务费/文化服务费"）
                        │
                        ▼
              供应商/大师傅执行仪式
                        │
                        ▼
         （如涉捐赠）Merit 引流 → 机构官方渠道
         用户直接在机构官方页面捐款，Merit 收引流/推介费
```

#### 核心规则（铁律）

1. **Merit 只收"代办服务费"，不碰捐款本金**
   - 用户付费 = 购买"代上香服务"/"代祈福服务"/"大师傅开示服务"
   - 账单描述：`Cultural ritual service fee` / `代祈福服务费`
   - **禁用词**：donation、捐款、功德钱、香火钱、charitable contribution
   - Stripe 入账商品类目：`services`，description 用文化/民俗/纪念框架

2. **涉及机构捐款的处理**
   - 若用户希望"向寺庙捐款"→ Merit 提供官方捐款渠道链接，用户在机构官方页直接完成
   - Merit 与机构签**引流推介协议**，机构向 Merit 支付引流/营销服务费
   - Merit 不出现在捐款资金链路中

3. **服务类 SKU（代上香/供灯/法事/超度）**
   - 完全按服务定价，用户购买"服务"而非"捐款"
   - 无需公示 margin（就像买餐厅代厨不需公示食材成本）
   - 高透明度但非强制：可自愿披露"部分服务费用于支持寺庙日常运营"

4. **供应商付款**
   - Merit 向供应商（大师傅/寺庙合作方）支付服务外包款，走正常 B2B 发票/合同
   - 不走"捐款"链路，明确为"服务采购"

#### 方案 A 的合规优势

- 无需 MTL 牌照（不托管资金，不做资金传输）
- 无需慈善注册（不募集捐款）
- Stripe 风控友好（service 类目而非 donation）
- 可立即在海外华人市场（美/澳/加/欧）运营

### 1.3 方案 B（代收代转）：后置，有牌照再谈

方案 B = 代收用户捐款 → 扣平台费 → 转给寺庙/机构，需要：
- 美国：各州 MTL（货币传输牌照），每州单独申请，申请周期 6–18 个月
- 美国：各州慈善募捐注册（若以公益/慈善名义）
- 跨境：AML/KYC 程序、FinCEN 报告
- 机构：必须有书面授权协议，且机构本身须是合法注册的宗教/非营利组织

**结论：方案 B 成本高、周期长、风险重。本 PRD 阶段完全不做，待方案 A 验证 PMF 后再评估。**

| 宗教/地区 | 扩展前提 | 时机 |
|---|---|---|
| 道教（国内/海外） | 道观合作协议+合规审 | Phase 1 后 |
| 藏传佛教 | 喇嘛资质+敏感文化审慎 | Phase 2 |

| 印度教（印尼/马来/北美印度裔） | 印度裔市场调研+供给 | Phase 3 |
| 天主教/神父祈福 | 教区授权+西方合规 | Phase 3 |
| 日本神社 | 神职人员合作+签证/礼仪 | Phase 3 |
| 犹太/伊斯兰 | 专项合规+社区调研 | 验证需求后 |

### 3.2 供应商核验铁律（防假视频骗子）

每个新供应商上架前必须小额真测（¥50–200 下一单代上香）：

- [ ] 真实地录像（非库存/换背景视频）
- [ ] 能配合实时 Agora 连麦（不能连麦 → 不进高客单 SKU）
- [ ] 照片/牌位含指定信息、按约定时间执行
- [ ] 供应商有明确的联系渠道和服务协议

通过核验 → 放量；高客单 SKU（法事/超度/烧替身）**只用能连麦、能实地直播的供应商**。

建立供应商评级档案 + 抽检机制，长期防"混单/批量假视频"。

### 4.3 大师傅连麦（核心差异化）

直接复用 `server/routes/video-call.js` + `server/lib/agora-integration.js`，连麦对象从"命理大师"扩展为"寺庙师父/主法居士"。

## 第七章 信任/履约体系

### 7.1 四层信任叠加

**Layer 1：实地录像**
- 每单在真实寺庙/道观实地拍摄仪式全过程
- 画面必须包含可辨识的寺庙标识/环境（排除棚拍/换背景质疑）

**Layer 2：Agora 实时连麦直播（最强差异化）**
- 用户全程实时观看仪式直播（不是录播）
- 仪式中/后可与师父实时对话
- 师父可为用户口头祈福+答疑
- 实时双向 = 造假成本极高 = 信任护城河

**Layer 3：定制照片凭证**
- 含用户姓名/祈福对象手写牌位近景照
- 仪式关键节点照（上香/点灯/回向时刻）
- 交付到账户中心永久留存

**Layer 4：书面回向凭证**
- 电子回向文书：含日期、寺庙名称、中性师父署名（"主法居士""寺庙法师"，不打名人 IP）
- 积累真实用户评价（参考湄洲妈祖案例）

### 7.2 履约 SLA

| SKU 类型 | 连麦要求 | 照片交付 | 文书交付 |
|---|---|---|---|
| 引流款（代上香/系红） | 可选（无连麦则提供录播+照片） | 24h 内 | 48h 内 |
| 中客单（供灯/代念经） | 可选 | 48h 内 | 72h 内 |
| 高客单（法事/超度/烧替身） | **必须实时连麦** | 即时+24h 精修版 | 24h 内 |

### 7.3 异常处理

- 连麦失败（网络/技术）：全额退款或重新安排，无条件
- 供应商未按约执行：平台先行赔付，向供应商追偿
- 用户投诉凭证造假：内部核查+供应商下架+退款

**1. 独立品牌 vs Runae 子频道？**
现在的方向是独立品牌（Merit 或另起名）通过大师傅打通 Runae。另一个选项是做成 Runae 内的"祈福供养"频道，不单独建品牌。两者影响：独立品牌获客成本更高但品类定位更清晰；子频道冷启动更快但稀释 Runae 算命定位。**需要 Karen 拍板品牌策略**。

供灯年供是最天然的订阅复购载体，但需要与寺庙签年度合作协议（确保灯一直点着+定期发照片凭证）。这需要 Karen 或团队主导谈寺庙合作，不是纯线上产品能自动解决的。**需要 Karen 确认是否有寺庙关系可直接切入**（五台山现有关系是否适合签年供合作？）。

**3. 第一批真实交易的启动方式？**
MVP 目标是前 10 笔真实交易验证全链路。最快的冷启动方式是：Karen 本人或亲近用户先下单（内测），走一遍完整链路（付款→连麦→凭证），确认供应商和技术可靠后再对外推广。**需要 Karen 确认：谁是第一批内测用户，五台山现有供应商是否可以马上启动连麦测试？**
