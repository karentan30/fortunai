┌──────────────────────────────────────────────────────────────────────────┐
│ 🚀 五分钟快速启动                                                          │
└──────────────────────────────────────────────────────────────────────────┘

1. 配置 Slack Webhook (https://api.slack.com/apps)
   └─ 创建 Incoming Webhook
   └─ 复制URL到 ~/.env.production

2. 运行部署脚本
   └─ bash scripts/monitoring-setup.sh

3. 验证系统
   └─ curl http://localhost:3007/health
   └─ 应返回: {"status": "healthy"}

4. 打开监控看板
   └─ open monitoring-dashboard.html

5. 发送测试告警
   └─ curl -X POST http://localhost:3007/alert/payment ...

系统管理:
  pm2 list                              # 查看进程状态
  pm2 logs shenyuan-alerts              # 查看日志(实时)
  pm2 logs shenyuan-alerts --lines 100  # 查看最近100行
  pm2 monit                             # 实时监控
  pm2 restart shenyuan-alerts           # 重启系统
  pm2 stop shenyuan-alerts              # 停止系统

API 调用:
  curl http://localhost:3007/health     # 健康检查
  curl http://localhost:3007/metrics    # 查询指标

  # 发送支付成功通知
  curl -X POST http://localhost:3007/alert/payment \
    -H 'Content-Type: application/json' \
    -d '{"type":"success","amount":99.9,"orderId":"test-001",...}'

  # 发送邀请激活通知
  curl -X POST http://localhost:3007/alert/invite \
    -H 'Content-Type: application/json' \
    -d '{"referrer":"user1","invitee":"user2","activated":true,...}'

  # 发送服务器指标
  curl -X POST http://localhost:3007/alert/server \
    -H 'Content-Type: application/json' \
    -d '{"memory":75,"disk":80,"cpu":45,"errors":3,"requests":250}'

┌──────────────────────────────────────────────────────────────────────────┐
│ 📝 API 端点说明                                                             │
└──────────────────────────────────────────────────────────────────────────┘

POST /alert/payment
  └─ 支付事件通知
  └─ 字段: type(success/failure) amount orderId userId error processingTime
  └─ 触发: 超过5%失败率 / 延迟>5秒时告警

POST /alert/invite
  └─ 邀请激活事件通知
  └─ 字段: referrer invitee activated activatedAt reward
  └─ 触发: 流失率>30%时告警

POST /alert/server
  └─ 服务器指标上报
  └─ 字段: memory disk cpu errors requests
  └─ 触发: 内存>80% / 磁盘>85% 时告警

GET /metrics
  └─ 查询当前指标(用于看板)
  └─ 返回: payment/invite/server/api 的所有统计数据

GET /health
  └─ 健康检查端点
  └─ 返回: {"status": "healthy", "pid": xxx}

什么时候调整告警阈值?
  • 当假告警频率 > 2次/天 → 可能需要提高阈值
  • 当真实问题未被捕获 → 可能需要降低阈值
  • 业务规模变化时 (容量规划)
  • 定期审视: 每月一次 (docs/alert-rules.md §定期审视计划)

什么时候需要扩容?
  • 内存持续 > 85% → 升级内存
  • 磁盘持续 > 90% → 清理旧日志或升级磁盘
  • CPU持续 > 80% → 考虑垂直或水平扩展

什么时候需要紧急干预?
  • 支付失败率 > 10% (关键收入) → 立即升级
  • 数据库连接失败 → 立即重启或主从切换
  • 磁盘满 → 立即清理或扩容

每日 (08:00 UTC):
  □ pm2 list              - 确认告警系统运行
  □ pm2 logs (last 50)    - 检查是否有错误

每周 (周一 14:00 UTC):
  □ 回顾本周告警频率      - 找出重复告警
  □ 检查磁盘空间          - df -h
  □ 检查内存占用          - free -h
  □ 审视告警规则有效性    - 有没有误报/遗漏

每月 (月末):
  □ 调整告警阈值          - docs/alert-rules.md
  □ 优化告警规则          - 根据业务变化
  □ 清理旧日志            - 避免磁盘满
  □ 更新文档              - 记录变更
